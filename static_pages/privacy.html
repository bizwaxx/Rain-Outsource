Privacy

Draft dated October 21, 2026. Covers the Rain-Outsource API and MCP server at rainout-agent-source.vercel.app. This page describes what the code in the public repository actually does.

The short version

The free tier has no accounts. You don't need a sign-up, an email or an API key. We don't sell data, we don't run ads or ad trackers, and these pages and the API set no cookies. We keep daily usage counts, short-lived rainout reports, and a cache of weather forecasts. We do not store IP addresses.

Usage counts

  • What is counted. For each day (Central time) we count requests per endpoint and calls per MCP tool. Each count is split by a coarse caller type: outside user, our own tests, uptime monitor, or search bot. The caller type is worked out from the request's User-Agent, and the User-Agent itself is not stored.
  • Unique visitors. To estimate how many different clients used the service on a day, your network (IP) address is run through a keyed one-way hash (HMAC-SHA256). The secret key changes every day, so the same client can't be matched from one day to the next. The result goes into a HyperLogLog counter, which keeps only an approximate total, not the hashes. The raw IP address is never stored.
  • First outside use. We keep one record of the very first outside request ever made. It holds the time, which endpoint or tool was called, a broad client family (for example "Claude" or "curl"), and the country our host reports for the request. It holds no IP address and no User-Agent.
  • How long. Daily counts are kept for about 400 days. The first-use record is kept until we delete it.

Rainout reports you choose to send

  • What we store. When you or your agent report a field as cancelled, delayed or playing, we store the field, the status, the game date and time, the time of the report, a random report id, and any note you add (up to 280 characters).
  • Who can see it. Reports are public. Anyone can read them at /v1/reports, and they can nudge the odds others see for that field. Please don't put names, phone numbers or other personal details in a note.
  • How long. Reports are deleted automatically after 24 hours.
  • Spam limits. To limit spam, the sender's network address is turned into a keyed one-way hash (HMAC-SHA256 with a secret key that changes every day) and used as an hourly counter key. That key expires within an hour, and it is never written into the report. Without the secret key, nobody can work out an address from the hash by trying addresses. We hold the key, so during that hour we could check whether a particular address matches. We don't do that.

Weather cache

We cache forecasts by place, so we don't ask the weather services the same question over and over. That cache holds weather data and coordinates, not information about who asked.

What we send to other services

  • Weather and place search. To answer a question we send the place's coordinates, or the place name you typed, to the US National Weather Service (api.weather.gov) and to Open-Meteo (forecasts and place search). We never send your identity. We identify ourselves to them with our own User-Agent.
  • Links you give us. If you give us a schedule or calendar link, our server fetches that link to read the games on it.
  • Official status pages. We read public official status pages from leagues, parks, venues and tracks.
  • Bundled data. Venue locations and past rainfall come from OpenStreetMap and NOAA data that ships with the code, so looking them up sends nothing to anyone.

Hosting

The service runs on Vercel, and its shared storage (the counters, reports and cache above) is Upstash Redis. Like any web host, Vercel handles each request, including your IP address, under its own privacy policy and may keep short technical logs. Our code does not copy IP addresses into our storage.

Calendars

Rain-Outsource never reads or writes your calendar. It can hand your agent a ready-made event, and your agent should ask you before adding it.

Children

The service doesn't ask for personal information from anyone, including children.
