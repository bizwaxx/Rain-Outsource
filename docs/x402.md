# Pay per call with x402 (testnet only)

`POST /v1/premium/batch` checks up to 50 games or 25 teams in one call. Callers with a
paid API key just send `X-API-Key`. Callers without a key can pay per call with
[x402](https://github.com/coinbase/x402) v2: no signup, just a wallet.

**This build is testnet only:** Base Sepolia test USDC, which has no value. Any other
network (including Base mainnet) is refused.

| | Value | Source |
|---|---|---|
| Network | Base Sepolia, CAIP-2 `eip155:84532` (chain id 84532) | https://docs.base.org/base-chain/quickstart/connecting-to-base |
| Asset | USDC `0x036CbD53842c5426634e7929541eC2318f3dCF7e`, 6 decimals, EIP-712 domain `USDC` / `2` | https://developers.circle.com/stablecoins/usdc-contract-addresses ; x402 `python/x402/mechanisms/evm/default_assets.py` |
| Scheme | `exact`, asset transfer method `eip3009` (`transferWithAuthorization`) | x402 `specs/schemes/exact/scheme_exact_evm.md` |
| Facilitator | `https://x402.org/facilitator` (public, testnet/dev only) | x402 `docs/core-concepts/facilitator.md` |
| Price | 0.02 USDC per call (`amount` `20000`), env `X402_PRICE_USDC` | proposal |
| Pay to | env `X402_PAY_TO` (Jimmy's wallet address) | — |

## Flow (x402 v2 HTTP transport)

1. `POST /v1/premium/batch` without payment → `402` with header `PAYMENT-REQUIRED`
   (base64 `PaymentRequired`: `x402Version: 2`, `resource`, `accepts: [{scheme: exact,
   network: eip155:84532, amount, asset, payTo, maxTimeoutSeconds: 60, extra: {name: USDC,
   version: 2, assetTransferMethod: eip3009}}]`). The body repeats it as JSON.
2. The client signs an EIP-3009 authorization for exactly `amount` to `payTo` and retries
   with `PAYMENT-SIGNATURE` (base64 `PaymentPayload`: `accepted` + `payload.signature` +
   `payload.authorization {from, to, value, validAfter, validBefore, nonce}`).
3. The server checks the payload against its requirements (network, asset, payTo,
   amount, validity window, nonce format, nonce not already used), then calls the
   facilitator's read-only `POST /verify` with `{x402Version, paymentPayload, paymentRequirements}`.
4. If valid, it runs the batch. If every item failed, it returns 502 and **does not settle**
   (no charge). Otherwise it calls `POST /settle` (the facilitator submits
   `transferWithAuthorization` and pays gas) and returns `200` with `PAYMENT-RESPONSE`
   (base64 `{success, transaction, network, payer}`).
5. If settlement fails, the result is withheld: `402` with a failed `PAYMENT-RESPONSE`.

v1 clients that send `X-PAYMENT` get a 402 telling them to use v2 (`PAYMENT-SIGNATURE`).

## Testing

* `tests/test_x402.py` uses a fake facilitator (challenge format, verify → run → settle,
  replay, mismatches, mainnet refusal, no charge on failure, settlement failure).
* `scripts/x402_testnet_probe.py` signs a real EIP-3009 authorization with a throwaway,
  unfunded key and calls only the public facilitator's read-only `/verify`. Result on
  2026-10-20: `isValid: false, invalidReason: invalid_exact_evm_insufficient_balance`,
  so the facilitator parsed the payload, recovered the signature and simulated the
  transfer on Base Sepolia USDC. Nothing was paid or settled.
* For a real end-to-end testnet payment: fund a test wallet from a Base Sepolia USDC
  faucet (e.g. https://faucet.circle.com) and use an x402 v2 client such as `@x402/fetch`.
